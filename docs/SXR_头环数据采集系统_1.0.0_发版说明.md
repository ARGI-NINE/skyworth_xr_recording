# SXR EGO 头环数据采集系统 1.0.0 发版说明

## 一、版本概述

1.0.0 版本面向头环多传感器数据采集场景，重点建立完整的采集、控制、记录和导出流程。系统以同一套时间戳关联相机、IMU、音频、头部位姿、手势和手柄数据，保证一轮采集可以作为完整数据集交付和后处理。

本版本的详细操作方法请参见：[1.0.0 使用说明](SXR_头环数据采集系统_1.0.0_使用说明.md)。

## 二、SDK 功能概览

### 1. 完整的头环数采能力

- 支持 RGB、Tracking、Ctrl 相机数据采集。
- 支持加速度计、陀螺仪、音频和头部 6DoF 位姿采集。
- 支持手势模式，保存手部关节数据。
- 支持手柄模式，保存左右手柄位姿数据。
- 手势模式和手柄模式可以按采集需求选择，均与相机、IMU、音频和头部位姿数据使用同一套时间基准。
- 每轮采集以独立 session 保存，并同时保留视频、传感器数据、时间戳、标定信息和采集日志。

### 2. 统一时间戳和采集信息

- 建立统一的 UTC 纳秒时间线，用于对应不同传感器的采样时刻。
- 相机帧提供曝光时间和帧时间信息，传感器数据提供对应采样时间戳。
- RGB 图像、IMU、头部位姿、手势和手柄数据可以按照同一时间基准进行匹配。
- 视频主要作为图像数据载体，时间对齐信息保存在视频旁边的元数据文件和传感器 CSV 中。

## 三、新增功能

### 1. 新增日志系统

本版本增加分层日志，便于判断设备连接、采集过程、数据收尾和导出是否正常：

- 应用日志：记录应用启动、设备连接、采集状态、传感器状态和错误信息。
- 单轮采集日志：随每个 session 保存，记录本轮采集的开始、停止、收尾和异常情况。
- U 盘导出日志：记录 U 盘识别、导出路径、复制过程、失败原因和拔盘事件。
- 采集状态文件：区分正在采集、收尾中和已完成，供导出和后处理判断数据是否可以使用。

### 2. 新增 App 交互能力

- 支持扫描并选择头环设备。
- 支持通过 App 配置设备 Wi-Fi，并保留最近使用的 Wi-Fi 配置。
- 支持设备已经联网时通过 IP 地址直接连接，减少重复配网操作。
- 提供统一控制页面，显示设备连接状态、电量、Wi-Fi 信号、存储空间、故障信息和实时预览。
- 支持通过 App 开始或停止录制，以及开始或停止手机端预览。
- 支持手机发起的采集和设备按键/ADB 发起的本地采集，并根据设备状态管理操作权限。
- 采集和预览之间支持按状态切换；正在采集时不能重复开始另一轮采集，互斥操作会被自动限制。
- 手机控制连接异常时，设备端正在进行的本地数据采集不会因为手机离线而被直接丢弃。

### 3. 新增 U 盘导出能力

- 支持识别可移动 U 盘并自动创建 `Export` 目录。
- 以完整 session 为单位导出，视频、传感器 CSV、位姿、标定信息和日志一起保存。
- 只导出已经完成收尾的 session，避免导出尚未写完的数据。
- 复制成功后再清理设备本地数据，复制失败、空间不足或中途拔盘时保留本地数据，便于重新导出。
- 增加语音提示，反馈 U 盘识别、导出完成、无待导出数据、导出失败和 U 盘卸载等状态。

## 四、问题修复

### 1. 修复 MP4Wrapper 视频时长异常问题

修复 MP4Wrapper 在写入视频时间轴时的时长计算问题。此前封装后的 MP4 可能出现播放器显示时长不准确、末帧时长未正确计入或不同帧时间间隔表达不一致的情况。

本版本按照相邻视频帧的时间戳计算帧持续时间，并在停止采集时正确完成最后一帧的时长写入，使 MP4 的时间轴与实际采集时间更一致。

### 2. 修复相机停止保存时的丢帧问题

修复 RGB、Ctrl 和 Tracking 三路相机在停止采集、停止保存阶段的帧处理问题。此前停止流程中，部分已经进入相机回调但尚未完成编码或写盘的帧可能未被保存，导致视频和对应元数据记录不完整。

本版本统一调整三路相机的采集、回调和停止收尾逻辑，在关闭相机和编码器前完成在途帧处理，再结束视频文件写入，避免停止阶段的帧丢失，并保持视频帧与元数据记录一致。
